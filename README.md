# NA2LAX | نَقْلِكس

موقع نقل عفش وأثاث — **Next.js 16 + TypeScript + Tailwind CSS 4 + Supabase**.

## التشغيل

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # نسخة الإنتاج: ملفات static في مجلد out/
npm start       # معاينة نسخة الإنتاج من out/ (بعد build)
npm run lint
```

## تعديل المحتوى

| الملف | المحتوى |
| --- | --- |
| `src/config/site.ts` | بيانات التواصل، الأسعار، الأسئلة الشائعة، عنوان ووصف جوجل |
| `src/config/services.ts` | صفحات الخدمات (نصوص، أسئلة، صور) |
| `src/config/areas.ts` | صفحات المناطق (الأحياء، النصائح، الأسئلة) |

- إخفاء الأسعار من الموقع بالكامل: `pricing.show: false`
- إضافة منطقة أو خدمة جديدة: أضف عنصرًا في الملف المناسب، وتُنشأ صفحتها وتُضاف لخريطة الموقع تلقائيًا
- الصور في `public/assets/`

## الصفحات

| الرابط   | الوصف                                          |
| -------- | ---------------------------------------------- |
| `/`      | الصفحة الرئيسية + نموذج الحجز                  |
| `/services` و `/services/[slug]` | 6 صفحات خدمات (ونش، تغليف، فك وتركيب...) |
| `/areas` و `/areas/[slug]` | 15 صفحة مناطق (التجمع، مدينة نصر، أكتوبر...) |
| `/track` | تتبع الطلب برقم الطلب                          |
| `/admin` | لوحة إدارة الطلبات (دخول بحساب Supabase)       |

روابط الموقع القديم (`admin.html` وصفحات الأدلة) تتحول تلقائيًا للصفحات الجديدة عن طريق ملفات تحويل في `public/`.

## Supabase (خطوة مهمة قبل النشر)

1. من **Authentication → Users** تأكد أن حساب الأدمن موجود.
2. افتح `supabase/schema.sql` وغيّر إيميل الأدمن في الخطوة 2.
3. شغّل الملف كاملًا من **SQL Editor**.
4. من **Authentication → Providers → Email** أوقف **Allow new users to sign up** (اختياري لكن مستحسن).

بعدها: الزوار يسجّلون طلبات فقط، وقراءة/تعديل/حذف الطلبات للأدمن فقط.

بيانات الاتصال بـ Supabase مضبوطة افتراضيًا، ويمكن تغييرها بمتغيرات البيئة (راجع `.env.example`).

## SEO (بعد النشر)

الموقع جاهز تقنيًا: عناوين ووصف لكل صفحة، بيانات منظمة (MovingCompany, Service, FAQ, Breadcrumb)، `sitemap.xml` و`robots.txt`. الخطوات التي تحتاج حساباتك:

1. **Google Search Console:** أضف الموقع، ضع كود التحقق في `site.seo.googleVerification` داخل `src/config/site.ts`، ثم أرسل `https://na2lax.com/sitemap.xml`.
2. **Google Business Profile:** أنشئ ملف الشركة بنفس الاسم والعنوان والتليفون الموجودين في الموقع — هذا أهم عامل للظهور في خرائط جوجل لبحث "نقل عفش".
3. اطلب من العملاء تقييمات على ملف الشركة في جوجل.
4. استبدل الصور الحالية بصور حقيقية لسياراتكم وفريقكم (الصور الحالية عليها أسماء شركات أخرى).

## النشر على GitHub Pages (na2lax.com)

الموقع static بالكامل (الحجز والتتبع ولوحة الإدارة تتصل بـ Supabase من المتصفح)، والملف `.github/workflows/deploy.yml` يبنيه وينشره تلقائيًا مع كل push على فرع `main`.

### أول مرة فقط

1. شغّل `supabase/schema.sql` (قسم Supabase بالأعلى) — مهم قبل جعل الـ repository عامًا.
2. أنشئ repository على GitHub (يجب أن يكون **Public** في الحساب المجاني) وارفع المشروع:

   ```bash
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```

3. من **Settings → Pages** في الـ repository:
   - **Source:** `GitHub Actions`
   - **Custom domain:** `na2lax.com` ثم **Save**
   - بعد تفعيل الـ DNS وظهور الشهادة: فعّل **Enforce HTTPS**
4. من لوحة شركة الدومين احذف سجلات `A`/`AAAA`/`CNAME` القديمة لـ `@` و`www`، وأضف:

   | النوع | الاسم | القيمة |
   | --- | --- | --- |
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | AAAA | `@` | `2606:50c0:8000::153` |
   | AAAA | `@` | `2606:50c0:8001::153` |
   | AAAA | `@` | `2606:50c0:8002::153` |
   | AAAA | `@` | `2606:50c0:8003::153` |
   | CNAME | `www` | `USERNAME.github.io` |

   تفعيل الـ DNS قد يأخذ حتى 24 ساعة.
5. (مستحسن) وثّق الدومين من إعدادات حسابك: **Settings → Pages → Add a domain**، حتى لا يستخدمه أحد في repository آخر.
6. من تبويب **Actions → Deploy to GitHub Pages → Run workflow** شغّل النشر. أول تشغيل مع الـ push غالبًا يفشل لأن Pages لم تكن مفعّلة وقتها — هذا طبيعي.

### بعد ذلك

أي تعديل: `git push` على `main` ويظهر على الموقع خلال دقائق (تابع التقدم من تبويب **Actions**).

> عند معاينة `npm start` على Windows قد تظهر أخطاء 404 في الـ console لملفات `__next.*.txt` — مشكلة في Next.js على Windows فقط، ولا تظهر في النسخة المنشورة لأن البناء يتم على Linux.
